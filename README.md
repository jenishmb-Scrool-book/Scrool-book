# СДВГ

Читалка для людей с СДВГ и тех, кто привык к быстрому вертикальному контенту.
ID пакета — `com.tirekai.sdvg`.

Вставляешь свою книгу — приложение режет её на короткие куски и показывает не как книгу, а как экран телефона. Заходишь в «Переписку» — текст приходит сообщениями. В «Клипы» — листаешь вертикально. В «Истории» — по касанию. В «Ленту» — читаешь постами. В «Видео» — читаешь описание под роликом. В «Короткие посты» — по паре предложений.

**Главное:** курсор общий и считается в символах, а не во фрагментах. Прочитал десять кусков в клипах, зашёл в переписку — продолжаешь ровно с той же строки, хотя куски там втрое короче.

## Стек

React 18 + Vite 6, обёрнутые в Capacitor 7. Тесты — Vitest. Зависимостей на рантайме нет: fb2 и epub разбираются своим кодом, epub распаковывается через нативный `DecompressionStream`.

```
src/
├── lib/chunk.js       нарезка текста на куски заданного размера
├── lib/toc.js         распознавание заголовков в обычном тексте
├── lib/fb2.js         разбор .fb2 (включая windows-1251)
├── lib/epub.js        разбор .epub (ZIP через DecompressionStream)
├── lib/storage.js     хранилище: Capacitor на Android, localStorage в браузере
├── store.jsx          весь стейт: книги, курсор, оглавление, настройки
├── screens/           Home, Chats, Reels, Stories, Feed, Video, Tweets, Chapters, Library, Settings
├── ui/skins.js        имена «приложений» и состав экрана у каждого мессенджера
├── ui/Tabbar.jsx      нижняя панель навигации
├── ui/                оболочка экрана, шапка, прогресс, окно рендера карточек
└── native.js          status bar, аппаратная кнопка «назад», уведомления
android/               проект для Android Studio (генерируется Capacitor)
docs/                  политика конфиденциальности (GitHub Pages) и заметки к выпуску
www_backup/            ванильный прототип, эталон поведения
```

## Почему это похоже на настоящие приложения

Обёртка держится не на палитре. Три «мессенджера» — один и тот же экран, и
различаются они составом: у одного нижняя панель, у другого поиск в шапке, у
третьего белая шапка и круглые пузыри без хвоста. Состав лежит в
[src/ui/skins.js](src/ui/skins.js), цвет — в CSS.

Правила, которые легко нарушить, не заметив:

- **Значки — одноцветные символы, не эмодзи.** Цветная эмодзи на цветной шапке
  читается как наклейка. Перед тем как взять новый символ, проверь, что он есть
  в шрифте и означает то, что нужно, — способ описан в `findings.md`.
- **В «видео» текст книги лежит в описании, а не в плеере.** В коробке 16:9 это
  двести пикселей высоты со своей прокруткой, читать там нельзя.
- **Названия «приложений» искажены** и лежат в одном месте: они видны и на
  иконке домашнего экрана, и в шапке самого экрана.

## Сборка под Android

Требуется Android Studio. Свой JDK у неё внутри — отдельные `java` и `gradle` ставить не нужно.

**Первый запуск.** Открой Android Studio → `Tools → SDK Manager` → поставь Android SDK Platform 36 и Android SDK Build-Tools. Без этого Gradle не соберёт проект: `targetSdk` поднят до 36, потому что новые приложения в Play с более низким уже не принимают.

**Открыть проект.** В Android Studio: `Open` → выбери папку **`android`**, не корень репозитория. Корень она не поймёт — там лежит фронт, а не Gradle-проект. Дождись, пока пройдёт Gradle Sync.

**Собрать и запустить на телефоне.** Включи на телефоне режим разработчика и отладку по USB, подключи, выбери устройство в списке вверху → `Run` (▶).

**Debug-APK:** `Build → Build Bundle(s) / APK(s) → Build APK(s)`.
Файл ляжет в `android/app/build/outputs/apk/debug/`.

## После правок фронта

Android не видит изменения в `src/` автоматически — в проект копируется собранный `dist/`:

```bash
npm run build && npx cap sync android
```

Или одной командой, которая ещё и откроет Studio:

```bash
npm run android
```

## Подпись и выпуск

Ключ подписи в репозитории не лежит и лежать не должен. Как его создать, что вписать в `android/keystore.properties` и что дальше делать в Play Console — в [docs/release/checklist.md](docs/release/checklist.md). Тексты карточки — в [store-listing.md](docs/release/store-listing.md), ответы для формы «Безопасность данных» — в [data-safety.md](docs/release/data-safety.md).

Пока `android/keystore.properties` не создан, релизная сборка собирается неподписанной, а не падает — отладка и тесты не должны требовать секретов.

## Версия

Версия одна на три места, и они не связаны автоматически:

| Где | Что |
|---|---|
| `package.json` | `version` — отсюда её берёт Vite и показывает экран «О приложении» |
| `android/app/build.gradle` | `versionName` — должен совпадать с предыдущим |
| `android/app/build.gradle` | `versionCode` — целое число, обязано расти на **каждой** заливке в Play |

## Приватность в коде

Два места, которые легко сломать незаметно:

- **Разрешения `INTERNET` в манифесте нет намеренно.** Приложение офлайновое, и отсутствие разрешения — единственное утверждение о приватности, которое пользователь может проверить сам. Появится внешний ресурс — разрешение придётся вернуть, а вместе с ним переписать политику и форму Data Safety.
- **Тексты книг исключены из облачного бэкапа** (`res/xml/backup_rules.xml`, `res/xml/data_extraction_rules.xml`). Не только ради приватности: у Auto Backup квота 25 МБ, и пара крупных fb2 отключила бы бэкап приложения целиком — вместе с позицией чтения, то есть с единственным, что нельзя переимпортировать.

## Известные ограничения

- Иконка и splash — заглушки Capacitor, надо нарисовать свои.
- Текст первого запуска лежит в `src/seed.js` и описывает приложение своими словами: добавили движок или формат — правится и он.
- PDF не поддерживается и не планируется. `.txt`, `.md`, `.fb2`, `.epub` и вставка текстом.
- У `.epub` глава равна файлу спайна, а не записи из NCX/nav: у книги с мелкой разбивкой оглавление выйдет грубее, чем в обычной читалке.
- После восстановления телефона из облачной резервной копии книги окажутся в списке, но без текста, пока файл не добавят заново. Позиция чтения при этом сохранится.
- Ориентация зафиксирована портретной (`AndroidManifest.xml`).
