# Выпуск в Google Play — что сделано и что осталось

Файл рабочий: правится по ходу. Всё, что помечено «владелец», делается руками
и без меня — там либо пароли, либо аккаунт, либо рисование.

## Осталось

### 1. Ключ подписи — владелец

Пароли ввожу не я. Команда (JDK из Android Studio уже содержит `keytool`):

```bash
"C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v -keystore sdvg-upload.jks -alias sdvg-upload -keyalg RSA -keysize 2048 -validity 10000
```

Положить `.jks` **вне репозитория** — например в `C:\Users\<вы>\keys\`.
Затем скопировать `android/keystore.properties.example` в
`android/keystore.properties` и вписать туда путь, псевдоним и оба пароля.
Файл уже в `.gitignore`.

Потерять этот ключ не смертельно — Play подписывает приложение своим ключом,
а загрузочный при утрате сбрасывают через поддержку. Но сброс занимает дни,
так что копию лучше сразу положить куда-нибудь ещё.

### 2. Иконка — владелец

Нужны два файла:

| Что | Размер | Куда |
|---|---|---|
| Иконка приложения | 432×432 PNG, значимое — в центральном круге ⌀ 288 | в Android Studio: `File → New → Image Asset` |
| Иконка для карточки Play | 512×512 PNG, без прозрачности | загружается в Play Console |

`Image Asset` сам разложит все mipmap-размеры и сделает адаптивную иконку.
Фон приложения тёмный (`#0b0b12`) — иконку стоит проверить и на светлой теме.

Хорошо бы, чтобы иконка не была ещё одним «книжным корешком»: приложение
маскируется под ленту, и иконка — первое, что это обещает.

### 3. Сборка для загрузки

В Play загружается **`.aab`**, а не `.apk` — частая потеря дня.

```bash
npm run build && npx cap sync android
```

Дальше в Android Studio: `Build → Generate Signed App Bundle`, либо

```bash
cd android && ./gradlew bundleRelease
```

Результат: `android/app/build/outputs/bundle/release/app-release.aab`.

### 4. GitHub Pages для политики — владелец

Репозиторий должен стать публичным (сейчас он локальный, без remote).
Затем `Settings → Pages → Deploy from a branch → main → /docs`.
Адрес политики выйдет вида `https://<логин>.github.io/<репозиторий>/privacy/`.

Перед публикацией **вписать почту** в двух местах `docs/privacy/index.html`
(помечены комментариями). Свою почту я туда не подставлял: публикация почты —
ваше решение, а не моё.

Внутренние заметки (`docs/plans`, `docs/release`) из публикации исключены
через `docs/_config.yml`.

### 5. Play Console — владелец

Порядок, в котором это реально проходится:

1. Создать приложение, выбрать «Приложение», бесплатное.
2. **Закрытое тестирование** — залить `.aab`, собрать **12 тестировщиков**,
   которые непрерывно остаются подписанными **14 дней**. Только после этого
   открывается заявка на продакшен. Это требование для личных аккаунтов,
   зарегистрированных после 13 ноября 2023 года.
3. Карточка приложения — тексты в `store-listing.md`.
4. Data Safety — ответы в `data-safety.md`.
5. Возрастной рейтинг — анкета IARC, ответы там же.
6. Целевая аудитория: 13+ (не для детей).
7. Проверка личности разработчика — Google требует её отдельно, занимает время.

**Двенадцать человек — самая длинная часть всей затеи**, и она ни от чего не
зависит. Собирать их стоит начинать сейчас, параллельно с остальным: люди
должны быть подписаны непрерывно, отписавшийся обнуляет свой срок.

## Проверить на устройстве после переименования

Переименование меняет ID пакета, поэтому:

- Старое приложение «Скролл» **останется** на телефоне отдельно, со своими
  книгами. Новое ставится рядом, с чистого листа. Старое удалять руками.
- Первый запуск после сборки: если экран белый — почти наверняка виновато
  убранное разрешение `INTERNET`. Тогда вернуть строку в манифест и сказать
  мне: значит, WebView всё-таки куда-то ходит.
- Проверить, что уведомление всё ещё приходит: канал уведомлений привязан
  к пакету, и на новом ID он создаётся заново.
