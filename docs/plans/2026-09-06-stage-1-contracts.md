## Контракт агента A — парсеры

```js
// src/lib/fb2.js
export function parseFb2(bytes: ArrayBuffer|Uint8Array): {title: string, text: string, chapters: {title: string, at: number}[]}
// src/lib/epub.js
export async function parseEpub(bytes: ArrayBuffer|Uint8Array): Promise<{title, text, chapters}>
```

- `at` — **смещение в символах** внутри возвращённого `text`, не индекс главы и
  не индекс фрагмента. Это тот же тип координаты, что и курсор в сторе.
- `text` — плоский текст с `\n\n` между абзацами. Разметку (`<emphasis>`,
  `<strong>`) выбрасываем: чанкер режет по абзацам и предложениям, разметка ему
  не нужна, а в React она всё равно не отрендерится (`dangerouslySetInnerHTML`
  запрещён — текст пользовательский).
- Не найден заголовок → `title: ''`, вызывающий подставит имя файла.

**Зависимости добавлять нельзя.** Обе задачи решаются нативно:

- **fb2** — это XML. `DOMParser().parseFromString(str, 'application/xml')`.
  Подводный камень: русские fb2 часто в **windows-1251**. Кодировку берём из
  XML-декларации (`<?xml ... encoding="..."?>`, читается из первых ~100 байт как
  latin1) и декодируем `new TextDecoder(enc)`. `TextDecoder` поддерживает
  windows-1251 нативно. По умолчанию utf-8.
  Проверять `doc.querySelector('parsererror')` — при ошибке кидать `Error`.
- **epub** — это ZIP. Читаем central directory руками (сигнатура `PK\x05\x06`
  для EOCD, `PK\x01\x02` для записей) и распаковываем `DecompressionStream('deflate-raw')`
  для method 8, сырые байты для method 0. `DecompressionStream` есть в Chrome 103+
  и в Android WebView 103+. Если его нет — кидать `Error` с ключом
  `lib.parse_failed_zip`, а не молча ломаться.
  Дальше: `META-INF/container.xml` → путь к OPF → `<spine>` даёт порядок глав →
  каждый XHTML чистим до текста (`textContent` после удаления `script`/`style`).

**Тесты обязательны** (`vitest`, рядом с исходником, как остальные). Минимум:
пустой ввод, битый ввод, windows-1251, смещения глав указывают на реальные
границы в `text`, epub без `DecompressionStream` даёт внятную ошибку.

**`Library.jsx`:** расширить `accept` до `.txt,.md,.fb2,.epub`, выбрать парсер по
расширению, показать ошибку через существующий механизм. Главы сохранять пока
некуда — стор их не хранит; вернуть их в `addBook` нельзя, поэтому **главы просто
логируются и выбрасываются**, а хранение появится на Этапе 2. Не менять сигнатуру
`addBook(title, text)`.

## Контракт агента D — уведомления

Решения владельца, менять нельзя: **раз в сутки в 12:00, без настройки времени,
без «пропускать, если уже читал», разрешение спрашивается после первой главы.**

- Плагин: `@capacitor/local-notifications` (версия под Capacitor 7).
- `src/native.js` дополняется, существующий контракт `initNative({onBack})` не ломается.
  Добавить: `export async function ensureNotifications()` — спросить разрешение и
  запланировать ежедневное уведомление; `export async function cancelNotifications()`.
- На вебе (не Capacitor) обе функции — no-op, резолвятся в `false`. Приложение
  запускается в браузере на каждом `npm run dev`, падать там нельзя.
- В `Settings.jsx` — секция с переключателем вкл/выкл, состояние в сторе через
  `setUi({notify: 'on'|'off'})`. **Поле `notify` в сторе уже добавлено мной**
  (значение по умолчанию `'off'`, валидация как у остальных). Агент только читает
  и пишет через `setUi`.
- Отказ в разрешении → показать `set.notif_denied`, флаг вернуть в `'off'`.
  Второй раз системный диалог не появится, поэтому нельзя оставлять вид «включено».
